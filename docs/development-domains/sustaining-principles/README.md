# 運用保守設計の心得 (WIP)

## 大原則： 運用保守フェーズを解像度高くイメージしながら開発する！

- 運用保守は、開発が終わってから始まるものではない - 直近の運用保守に必要な道具立ては、リリース時点で揃っている必要がある
- 変えることはリスクだが、動かし続けるためには変え続ける必要がある - 変更と安全の両立を設計する
- システムを持続可能にするには、過去の失敗から学び、現在を正しく把握し、未来を予測する努力のサイクルを設計する
- 何が起こるかはわからないが、想定外のことが必ず起こるということはわかっている

---

## 前提：本ガイドにおける用語の定義について

「運用」と「保守」は一括りに語られることが多いが、担う問いが異なる。

| 用語   | 定義                                               | 担う問い               |
| ------ | -------------------------------------------------- | ---------------------- |
| `運用` | 動いているシステムを日々監視・維持する活動         | 今、正しく動いているか |
| `保守` | システムに変更を加える活動（機能追加・修正・更新） | 安全に変えられるか     |

本ガイドは、運用保守フェーズに向け、**開発フェーズから設計に組み込むべき関心事**として、以下の 3 領域を扱う。

- `delivery`（CI/CD）→ **保守**の設計：変更を安全・継続的に本番へ届ける仕組みを作る
- `observability` → **運用**の設計：稼働中のシステムの内側を見通す仕組みを作る
- `incident` → **運用・保守**の設計：インシデントに備え、対応し、学ぶ仕組みを作る
