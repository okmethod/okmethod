# エンジニアとPMの二人三脚理論

エンジニアリングとプロジェクトマネジメントは、別の専門領域。  
プロジェクトを成功させるためには、エンジニアとPMの双方が専門家として自分の領分に責任を持ち、 **「二人三脚」** で取り組むのが理想。

しかし、PMの関心事を理解しないまま協働しようとしても、的を射た助言も、建設的な分担も生まれない。  
そのため、PMBOK のPM知識エリアをベースとしつつ、各エリアのスタンスを明らかにすることで、「二人三脚の役割分担のイメージ」の擦り合わせを試みる。

## 二人三脚とは

**二人三脚**: エンジニアとPMがそれぞれの専門性を持ち寄り、共同でオーナーシップを担うイメージ。  
きっちりと線を引いて「どちらかに任せる」のではなく、「両者が主体的に動き、噛み合わないと機能しない」という強い依存関係・信頼関係を指す。

役割分担を考えるときの軸は **「誰が主導するか」**。

- 技術的判断が絡む → エンジニアが主導する
- 技術的判断が絡まない → PMが主導する

**「PMが主導する」は「エンジニアが関与しない」ではない。**  
主導しない領域でも、エンジニアとして果たすべき **インプット責任** がある。

### 二人三脚ではない例（アンチパターン）

このような姿勢は、二人三脚とは言えない。

- **押し付け合い**: 互いに「それはあなたの仕事」と責任を押しつける
- **寄りかかり**: 片方が自分の領分でベストを尽くさず、もう片方に負荷が偏る
- **引きずり**: 片方がペースを乱し、もう片方がそれに合わせることを余儀なくされる
- **分断並走**: 互いに自分の仕事をしているように見えるが協働しておらず、責任の隙間にボールが落ちやすい

特に、「寄りかかりに対する指摘」と「押し付け合い」は一見区別がつかない点に留意が必要。  
そうならないためにも、双方で共通した「二人三脚の役割分担のイメージ」を持つことが重要となる。
